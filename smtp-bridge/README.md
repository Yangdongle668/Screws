# 自建SMTP接入部署说明

本地/云端测试：运行 `npm ci` 后执行 `npm test`，需要 OpenSSL（Linux 通常可直接使用；Windows 可使用 Git for Windows 自带版本，或用 `OPENSSL_BIN` 指定路径）。测试自动生成一次性的 localhost 证书与独立临时回执目录，结束后清理，不读取真实证书、不连接外部邮箱、不发送实际邮件。

此服务尚未部署到你的服务器，不能仅保存网站SMTP表单就开始发信。Sites托管不能直连SMTP，由此服务通过465 SSL/TLS或587强制STARTTLS连接邮箱，网站通过HTTPS调用。

1. 在支持Docker的服务器复制本目录，将`.env.example`复制为`.env`，设置安全随机BRIDGE_TOKEN（至少32字符）；SMTP_ALLOWED_HOSTS填写实际邮箱域名，SMTP_FROM_DOMAINS限定发件域名。不要提交真实`.env`到Git。
2. 运行`docker compose up -d --build`。仅映射到服务器本机127.0.0.1:3001，不要暴露HTTP端口。
3. 参考nginx.example.conf，为你控制的专用域名配置可信HTTPS证书及443反向代理至127.0.0.1:3001。示例域名和证书路径必须替换为真实配置。请求体限制80KB，超时约25秒；关闭请求体与Authorization日志，不在URL中携带令牌。此操作不修改MX和现有邮箱配置。
4. 网站后台“邮件通知”填写SMTP主机、465/SSL或587/STARTTLS、登录邮箱、密码、可选From及接收人。高级部署设置填上述HTTPS域名和相同令牌。先保存、诊断TLS，再启用发送并测试实际收件。
5. 自动确认默认关闭，仅针对启用之后的新询盘，每个邮箱每天最多3封，不携带询盘正文或图纸。SMTP接受不等于最终送达。

服务固定校验证书有效期、名称和信任链。自建CA可在后台提供PEM。密码、令牌由网站加密保存，经HTTPS传输到你控制的转接服务；服务不记录正文或凭据。

`/data`仅保存散列请求编号、状态和时间，必须使用持久卷且单实例运行。已接受的同编号请求不会重发。进程中断、SMTP结果不明或部分收件人拒收时保留pending回执并拒绝自动重发；须先核实SMTP日志，再人工处理。不要盲目清除pending或运行没有共享回执的多实例。回执建议保留30天，清理前确认旧询盘不会再重试；清理会失去旧请求去重保护。

独立保管此持久卷、邮件设置和运行时加密密钥。网站手动备份不包含SMTP密码或这些运行配置。转接服务部署地址和服务器访问仍需你提供；不要在聊天中发送密码。
