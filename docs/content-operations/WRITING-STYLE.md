# Natural engineering writing principles

Write for an engineer or buyer making a specific decision. Explain the actual interface, material condition, trade-off, failure mode, required drawing input and next action when relevant. Prefer concrete, source-backed statements over generic claims about quality, innovation or precision. Do not invent measurements, shop-floor anecdotes, customer experience, tests or credentials to make prose sound human.

Use natural professional English. Vary sentence and paragraph length when the reasoning calls for it; do not mechanically apply a pattern. Remove redundant introductions, repeated conclusions, empty transitions, unnecessary em dashes and promotional adjectives. Shared technical terminology and accurate standards language must stay intact. Do not replace precise terms with awkward synonyms merely to lower a style-risk score.

Do not follow an "AI detector evasion" template, insert intentional errors, fake a personal voice or claim a low heuristic score proves human authorship. Writing-risk checks are editorial hints, not authorship percentages. If the content was produced in an AI-assisted workflow, preserve that known provenance in backend records.

SEO follows reader intent. Use one specific primary topic, useful related terms, an honest title and a distinct meta description. Answer the question early, then explain assumptions, alternatives and evidence. Avoid keyword stuffing, a fixed density target, invented PAA observations, fabricated search metrics or promises of ranking. Prefer improving a related existing page when it already serves the same need.

Technical blogs resolve one engineering question; industry insights explain a verified development and its limits; guides provide an executable workflow; existing-page reviews make targeted evidence-backed corrections. Do not flatten these tasks into the same essay outline. Translations preserve the approved meaning, numbers, grades, citations, metadata and links while using natural local engineering language.

The writing model returns structured content and never invokes publication tools. English articles enter human review. The server may automatically translate and publish a complete new technical article after explicit English approval, using the configured API budget and revision/translation checks. Other page patches still require manual integration. Uncertain, incomplete or materially changed content must stop for review.
