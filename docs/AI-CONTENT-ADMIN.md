# AI API 与定时内容维护（独立Docker）

更新部署后进入 `/admin/#ai`。不需要在部署脚本传入AI密钥：在中文后台设置即可。默认定时开关关闭，密钥与模型为空；没有设置就不会发起付费请求。

## 配置与首次执行

1. 运行 `bash update.sh`，登录后台打开“AI内容维护”。
2. 输入公开HTTPS API基础地址（例如服务商提供的 `/v1` 地址）、模型ID与API密钥。本实现采用Chat Completions兼容协议，不支持任意厂商原生消息协议。模型需遵循JSON输出；可选择max_completion_tokens或max_tokens，切换JSON模式以适配服务商。
3. 保存后测试已保存的API。测试有一次小额模型调用，也计入预算。API连接成功不等于文章质量已审核。
4. 可选配置Brave Search API密钥，用于发现新资料；检索有独立账单。也可提供明确的官方HTML参考网址。模型API不自动获得联网能力。抓取只允许配置的公开来源域名，拒绝私有地址，不跟随重定向，不解析PDF。页面读取失败会跳过；没有可读资料则HOLD，不伪造来源。
5. 先手动试运行，检查计划、对照正文、来源和输出。再启用定时开关。

## 调度与预算

- Docker应用每60秒检查队列，无需主机额外crontab。应用必须持续运行；后台浏览器可以关闭。
- 固定北京时间Asia/Shanghai，默认每周一9点技术博客；每月1/15日行业洞察；每月8/22日旧文复核。
- 停用计划仅停止新增计划任务；排队任务可在详情取消，运行中任务等待本次结束。
- 启用前的时间槽不补跑；中断恢复最多检查最近7天的到期槽。唯一slot键防止重复排队。串行执行模型任务。
- 默认每天最多新增6个任务、每月最多60个模型请求、2,000,000计入Token、每次正文最多6000输出Token。
- 调用前按输入UTF-8字节数+输出上限+额外余量保守预留；正常响应按usage核算，失败或usage缺失保留预留。月度计费窗口按UTC月份记录。额度可后台修改。
- Token/请求限制不是货币金额或搜索费用限制。务必在模型及检索服务商设置账单预算。每个任务通常含选题计划与写作两次模型调用，翻译一次。
- 失败不会无限自动重试，可人工重试，总执行不超过3次。服务重启中断中的任务标为失败，避免不确定请求自动重发计费。

## 内容记忆与审核

运行时读取随镜像打包的英文台账，并合并数据库中已发布或撤回的英文博客。现有草稿单独列出，作为避免重复选题的参考。写作先提出缺口假设和对照路径，再读取所选页面全文与公开来源后生成正文。

任务按六类英文Prompt执行，后台可编辑、保存与恢复默认；固定原则始终附加。自定义Prompt不能替代来源、预算、审核或网络边界。

每次任务保存计划、对照页面hash、Prompt hash、已获取来源、正文、状态和审核记录。审批前再次比较内容hash；对照页已改则需重新生成审核。审核通过不等于发布。

- 技术博客：审核通过、有完整结构化文章且URL未占用时，可“转入文章管理”，使用既有验证和草稿存储。仍需在原编辑器单独发布。
- 行业洞察、指南、旧文/商业页补全：保存并下载审核稿，按对应源文件/页面合并，不自动写入技术博客路由。
- 翻译：仅针对已批准英文任务创建，关联英文审批结果hash；英文版本已变会拒绝执行。输出语言稿仍需审核。未实现译稿自动写入现有翻译编辑器。
- 目前不能从任务调度器自动发布、修改生产源码或提交GitHub；也不代表已替代人工工程复核。

## 保存、安全和备份

SQLite中的ai_config/ai_jobs/ai_calls/ai_events保存配置、任务和预算权威状态。配置用MAIL_CONFIG_KEY派生独立AES-256-GCM密钥加密，API只返回密钥是否已保存，不回显值。保留MAIL_CONFIG_KEY才能迁移配置；不要在聊天或仓库中保存密钥。

`data/ai-content/inventory.json`、`task-ledger.json`及任务ID.json保存可读台账和稿件副本，由数据库任务状态重建。每次状态变化另存不可变revision文件并追加审计事件，保留审批前后的历史。默认文件权限受限。文件写入采用随机临时文件原子替换；单进程串行任务与SQLite状态声明共同防止重复执行。部署方式为单实例，不支持多个副本共享SQLite挂载。

使用现有 `bash backup.sh` 备份整个data与.env.docker，可覆盖这些数据。后台普通业务备份导出不包含AI专用配置和文件，不可用它单独迁移AI服务。

API在现有Docker管理员会话边界内，只接受本站Origin的POST写操作。外部访问使用公开HTTPS、DNS校验和固定解析地址，拒绝内部地址与跨域跳转。模型上下文不读取询盘、图纸、邮箱密码或客户附件。

## 验证

`node docker/verify-ai.mjs` 使用临时数据库和注入的虚构模型/来源响应，不发送付费请求。验证预算、审批、翻译版本、来源拒绝、定时去重、密钥加密、持久化和网络目标规则。

`node docker/build.mjs` 后运行 `node docker/verify-runtime.mjs` 验证实际管理员鉴权与Docker路由集成。首次真实API连通性需要管理员在后台提供自己的服务信息才能验证。
