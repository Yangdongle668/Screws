# AI API 与定时内容维护（独立Docker）

更新部署后进入 `/admin/#ai`。不需要在部署脚本传入AI密钥：在中文后台设置即可。默认定时开关关闭，密钥与模型为空；没有设置就不会发起付费请求。

## 配置与首次执行

1. 运行 `bash update.sh`，登录后台打开“AI内容维护”。
2. 输入公开HTTPS API基础地址（例如服务商提供的 `/v1` 地址）、模型ID与API密钥。本实现采用Chat Completions兼容协议，不支持任意厂商原生消息协议。模型需遵循JSON输出；可选择max_completion_tokens或max_tokens，切换JSON模式以适配服务商。
3. 保存后测试已保存的API。测试有一次小额模型调用，也计入预算。API连接成功不等于文章质量已审核。
4. 默认公开网页检索，无需搜索API密钥：后台按模型检索词直接访问公开搜索结果、发现可靠发布方页面并抓取HTML正文。搜索无可用结果时从允许来源站点的技术目录继续寻找，参考网址可以留空。只访问公开HTTPS来源，跳转仍需通过公开地址和来源域名校验；不绕过验证码，不解析PDF。任务记录返回数、筛选数和失败原因；缺少正文则暂缓。DeepSeek/Brave付费检索保留为可选模式，只有主动选择时才使用。
5. 先手动试运行，检查计划、对照正文、来源和输出。再启用定时开关。

## 调度与预算

- Docker应用每60秒检查队列，无需主机额外crontab。应用必须持续运行；后台浏览器可以关闭。
- 固定北京时间Asia/Shanghai，默认每周一9点技术博客；每月1/15日行业洞察；每月8/22日旧文复核。
- 停用计划仅停止新增计划任务；排队任务可在详情取消，运行中任务等待本次结束。
- 启用前的时间槽不补跑；中断恢复最多检查最近7天的到期槽。唯一slot键防止重复排队。串行执行模型任务。
- 默认每天最多新增6个任务、每月最多60个模型请求、2,000,000计入Token、每次正文最多6000输出Token。
- 调用前按输入UTF-8字节数+输出上限+额外余量保守预留；正常响应按usage核算，失败或usage缺失保留预留。月度计费窗口按UTC月份记录。额度可后台修改。
- Token/请求限制不是货币金额或搜索费用限制。务必在模型及检索服务商设置账单预算。每个任务通常包含选题、提纲、正文三次模型调用；选题格式修正会增加一次调用，翻译一次。
- 失败不会无限自动重试，可人工重试，总执行不超过3次。服务重启中断中的任务标为失败，避免不确定请求自动重发计费。

## 内容记忆与审核

运行时读取随镜像打包的英文台账，并合并数据库中已发布或撤回的英文博客。现有草稿单独列出，作为避免重复选题的参考。写作先提出缺口假设和对照路径，再读取所选页面全文与公开来源后生成正文。

任务按六类英文Prompt执行，后台可编辑、保存与恢复默认；固定原则始终附加。自定义Prompt不能替代来源、预算、审核或网络边界。

每次任务保存计划、对照页面hash、Prompt hash、已获取来源、正文、状态和审核记录。审批前再次比较内容hash；对照页已改则需重新生成审核。完整技术博客、行业洞察、工程指南和旧文更新审核后，统一自动翻译发布；旧文覆盖前保存六语言回滚版本。非文章页面补丁仍需人工合并。

- 技术博客：审核通过、有完整结构化文章且URL未占用时，自动保存英文草稿、翻译五种语言，并在全部校验通过后一次性发布六种语言。文章管理显示来源及进度。旧审批任务需手动启动新流程。
- 行业洞察、指南、旧文更新：完整结构化文章审核后自动翻译发布；各自保留正确栏目，旧文覆盖原网址。非文章商业页面补丁保留原处理方式。
- 翻译：完整技术博客使用版本绑定的结构化译文自动保存与发布，保留数字、牌号和链接；不确定或失败时停止，成功译文缓存后可重试。独立手动翻译任务仍生成待处理稿。详见 ARTICLE-WORKFLOW.md。
- 目前不能从任务调度器自动发布、修改生产源码或提交GitHub；也不代表已替代人工工程复核。

## 保存、安全和备份

SQLite中的ai_config/ai_jobs/ai_calls/ai_events保存配置、任务和预算权威状态。配置用MAIL_CONFIG_KEY派生独立AES-256-GCM密钥加密，API只返回密钥是否已保存，不回显值。保留MAIL_CONFIG_KEY才能迁移配置；不要在聊天或仓库中保存密钥。

`data/ai-content/inventory.json`、`task-ledger.json`及任务ID.json保存可读台账和稿件副本，由数据库任务状态重建。每次状态变化另存不可变revision文件并追加审计事件，保留审批前后的历史。默认文件权限受限。文件写入采用随机临时文件原子替换；Node.js工作线程池、SQLite状态声明与持久化选题占用共同控制并发。部署方式为单实例，不支持多个副本共享SQLite挂载。

使用现有 `bash backup.sh` 备份整个data与.env.docker，可覆盖这些数据。后台普通业务备份导出不包含AI专用配置和文件，不可用它单独迁移AI服务。

API在现有Docker管理员会话边界内，只接受本站Origin的POST写操作。外部访问使用公开HTTPS、DNS校验和固定解析地址，拒绝内部地址与跨域跳转。模型上下文不读取询盘、图纸、邮箱密码或客户附件。

## 验证

`node docker/verify-ai.mjs` 使用临时数据库和注入的虚构模型/来源响应，不发送付费请求。验证预算、审批、翻译版本、来源拒绝、定时去重、密钥加密、持久化和网络目标规则。

`node docker/build.mjs` 后运行 `node docker/verify-runtime.mjs` 验证实际管理员鉴权与Docker路由集成。首次真实API连通性需要管理员在后台提供自己的服务信息才能验证。

外部来源现为全部可选，行业洞察也不例外。后台“行业洞察尝试联网参考”默认关闭，开启后检索失败仍可继续定性分析。技术博客、指南和普通更新不再强制检索，交付 JSON 可用空 sources 数组；没有来源不扣SEO基础分。


## 新文章选题与旧文更新

- 技术博客、行业洞察、工程指南固定为“新文章”；只有“旧文补全复核”可选择更新已有文章。服务端约束优先于自定义Prompt。
- 新任务先读取仓库内容、运行时发布内容、草稿与选题占用。已发布网址上的待审核更新也保留记录。发现重复最多重选一次，仍重复则“无需修改”，不消耗翻译调用。
- 本地检查规范化标题、关键词、读者问题与正文片段；相近选题再做独立搜索意图复核。它们是编辑筛查，不能保证穷尽语义相同的所有表达，也不是Google评分。
- 选题占用保存到SQLite，工作线程通过事务和版本比较抢占。不同主题继续并行；同一主题和同一更新目标不能重复进入审核。失败、取消、退回、完成发布后不再占用；删除任务时对应占用记录一起删除。
- 旧文默认最短更新间隔30天，后台可设0–365天；仅手动旧文任务可明确勾选近期更新例外。例外不绕过去重、增量检查或审核。
- 更新稿对比引言、章节、清单与示例，展示真实修改和删除段落。短小的数值或适用条件修正也会进入纠错复核，而非只看字数。正文增量通过本地筛查后，还需独立模型确认新增读者决策或纠错价值；纯改写、堆字数与重复提醒不能作为更新理由。
- 独立意图/增量复核调用共用现有预算；不强制外部引用，不拆分完整正文生成。英文审核后仍按原链路翻译五种语言并统一发布，覆盖旧文前保留回滚快照。生成到审核期间若有人修改旧文草稿，原稿指纹校验会阻止覆盖。
- 更新不会自动清理生产环境已存在的相近稿件或历史任务。审核前请核对“新文章／旧文更新”、目标网址及实际差异。

验证：`node docker/verify-ai-topics.mjs`（临时数据库、模拟模型响应、无外部调用）；另运行工作线程、发布链路及覆盖台账回归测试。

## PAA接入与选题复核修正（2026-11-03）

PAA采集与文章生成使用同一持久化数据库。生成任务先读取近30天的英文问题（最多300条候选记录），过滤后只采用浏览器或SerpApi采集标记；单条记录损坏不会丢弃其余问题。选题PLAN收到最多24条线索，提纲OUTLINE再收到最多12条与选题匹配的问题，不会因生成文章额外发起付费PAA采集。

任务详情中的“PAA接入”显示全部、有效、匹配和采用数量及读取状态。无可用记录时继续普通关键词与意图分析；改写或未观察到的问题保留为推断问题，不冒充真实Google PAA，也不阻止写作。采用记录保留国家、语言、采集时间和来源；这不是搜索量或排名数据。

提纲阶段使用精简的选题提示词；完整正文、SEO、Schema交付要求只在正文阶段执行。选题独立复核兼容明确的同义字段，缺少非必要说明不再判失败。无有效结论时只定向修复一次，仍无判断则保留诊断和检查点，不能绕过防重复检查生成正文；重试继续复核，不重复已有效的选题与提纲。每次修复调用仍计入正常预算。

更新服务器执行 `bash update.sh`。历史失败任务不会自动重新收费执行，可在后台手动重试；新版本提示词会使旧流程检查点失效并按新规则运行。默认仍为一次返回完整文章，英文审核后翻译并统一发布六种语言。
