# 云端维护交接

## 仓库与线上状态

正式源码仓库为 `Yangdongle668/Screws`，默认分支 `main`。保留原提交历史与 Sites 项目标识。GitHub 是代码维护入口，线上网站仍由 Sites 托管；没有建立“合并即上线”的自动部署链路。

云端环境克隆仓库，安装 Node.js 24，再运行 README 中的命令。不依赖原 Windows 电脑路径。网页所需 WebP 图片已入库；原始生成 PNG 不参与构建。`prepare-application-images.mjs` 仅是重新压图工具，需要另行提供原图，不是构建步骤。

## 每次修改

1. 从最新 `main` 建立分支，修改内容源或功能。
2. 重新生成页面，检查新增入口、站点地图与 LLMS。
3. 运行相关检查，提交源与生成结果，通过 PR 审阅合并。
4. 在受授权环境发布到原 Sites 项目，记录实际发布结果。不要把本地检查写成已上线、已收录或已经发信。

## 生产数据不随克隆迁移

需独立管理 D1 中的询盘、备注、文章草稿/发布/历史、统计和加密邮件配置，以及 R2 上传图纸。后台发布内容可能覆盖仓库的基础文章，迁移时不能只拷贝 HTML。

后台备份不含运行时加密密钥、SMTP 凭据及独立转接服务的回执卷。邮件配置恢复依赖原密钥，应在受保护位置独立保管。不要上传数据备份到此公开仓库。
