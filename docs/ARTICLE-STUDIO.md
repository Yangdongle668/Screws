# AI文章工坊（新版文章生成）

后台位置：管理中心 → **AI文章工坊**。使用“AI内容维护”中已保存的模型、API密钥和预算，不需要另外配置。生成结果先进入人工审核，审核通过后交给现有的六语言翻译发布流程。

## 为什么重做

旧流程把选题、复核、提纲、正文、格式修复、增量复核等都交给模型，每篇5–8次调用；长文章用JSON输出，一个括号或引号错误就整篇作废；多层提示词互相冲突；真实性和查重依赖模型自觉。新流程的原则是：**服务器能确定的事不交给模型，模型只负责写。**

## 流程

| 步骤 | 执行者 | 说明 |
|---|---|---|
| 1. 选题 | 服务器，0次调用 | 候选来源按优先级：手动提示 → Search Console中有曝光但没有专门页面的搜索词 → 未用过、未被已有页面回答的PAA问题 → 支持文章最少的产品/工艺/材料页。与已有文章标题和待审任务做相似度比对，重复的题目直接排除。同时匹配主产品页和相关工艺页。 |
| 2. 写作简报 | 模型，1次小调用 | 标题、主关键词、读者问题、两三句话答案、分类、4–7个章节、FAQ问题、从给定列表中选择的内链。服务器剔除不存在的链接，确保包含主产品页。标题再与已有文章比对一次。 |
| 3. 正文 | 模型，1次调用 | 纯文本 `@@` 分段格式（不是JSON），引号、括号、换行都不会让整篇作废。写作规则只有一套，由服务器统一下发。 |
| 4. 本地检查 | 服务器，0次调用 | 见下表。 |
| 5. 修订 | 模型，最多1次 | 只有出现“拦截”或“需修订”问题时，带具体问题清单修订一次。 |
| 6. 人工审核 | 管理员 | 可直接修改正文，保存后只在本地重新检查，不调用模型。 |
| 7. 发布 | 现有发布流程 | 审核通过后自动翻译德、西、意、法、中五种语言，并统一发布六种语言。进度、每种语言的状态和错误直接显示在工坊的任务详情里；未完成时可在同一处点“重试未完成的翻译与发布”，已完成的语言不会重复翻译。 |

每篇通常2次、最多3次模型调用。

## 检查项

| 级别 | 含义 | 检查内容 |
|---|---|---|
| 拦截 | 不能发布 | 关于ZUFEK的认证/资质、客户或品牌供货关系、“我们测试/观察/经验”、公司数字不在 `COMPANY-FACTS.md` 中；与站内任一页面连续词句重合超过20%；标题与已有文章几乎相同；网址已被占用；输出不完整 |
| 需修订 | 交给修订调用 | 标题、搜索标题、Meta描述长度；主关键词未出现在标题或引言；引言超过4句；章节数；正文少于800或多于2600词；内链无效、少于3个或未链接主产品页；FAQ少于3条；第一人称；绝对化承诺；与站内页面重合8–20%；重复句子；讨论资料/证据本身的“研究备忘录”句子；空泛套话；保留说明过多；写作风格风险分≥50 |
| 人工核对 | 只提示 | 具体性能数值（MPa、N·m、%、小时等）；提到ZUFEK设备、产能或团队 |

“写作风格风险分”是基于句式和用词的风格提示，不是AI生成比例，也不能证明作者身份。查重比较的是本站已有内容；如需检查与外部网站的重复，请另用外部查重工具。

## 多语言

新文章使用与旧流程相同的六语言发布流程。翻译阶段已有的保护继续生效：来源和内链网址由服务器按英文原稿恢复；数字、牌号、标准号严格比对（计数词与数字互换除外）。

## 定时生成

在“定时生成”中选择星期（0为周日）和北京时间。到点后自动创建一篇，生成结果进入待审核，不会自动发布。

**建议**：启用新版定时生成后，在“AI内容维护”中关闭旧版的定时任务，避免两套流程同时选题。旧版流程仍保留，可随时切回。

## 失败处理

- **失败**（例如模型未配置、网络错误）：点“重试”，已完成的选题、简报和正文会被保留，不重复调用。
- **被拦截**：可以直接修改正文后保存（不调用模型）；也可以选“重写正文”（保留选题和简报），或“换一个选题”。
- **服务重启**：中断的任务标记为失败，已完成的步骤保留。
- **翻译或发布未完成**：在任务详情的“六语言发布”中查看是哪种语言、什么错误，点“重试未完成的翻译与发布”。每种语言最多尝试10次；格式问题导致的失败会先重新解析已保存的模型输出，不重新收费。

- `docker/studio-checks.mjs` 真实性、查重、SEO、风格检查
- `docker/article-studio.mjs` 任务、调度、接口
- `public/studio-admin.js`、`scripts/studio-admin.mjs` 后台界面

验证：`node docker/verify-article-studio.mjs`（模拟模型，使用真实站点清单查重）；`node docker/build.mjs` 后运行 `node docker/verify-studio-publish.mjs`（真实文章校验与发布队列）和 `node docker/verify-runtime.mjs`。
